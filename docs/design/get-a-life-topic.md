# Get-a-Life 主題與留言資源

## 需求與範圍
將 Get-a-Life 初版介紹與後續開源分享收為一張主題卡，讀者在同頁依時間讀兩篇完整原文，並直接開啟作者留言補充的GitHub、後續分享等已查證相關連結。
只處理這兩篇；不自動盤點或匯入全站所有留言。留言補充與原文分開呈現，不改寫原文、不生成摘要。

## User Journey
1. 在首頁或作者頁搜尋Get-a-Life／曼陀羅，只看到一張主題卡「Get-a-Life：生活規劃工具與開發歷程」。
2. 開啟主題頁，看到相關資源連結與6/21初版介紹、6/23開源心得兩節。每節保留原標題、日期、作者、Facebook來源、互動數與原照片。
3. 點GitHub等資源直接前往實際目的地，另可追來源留言。兩篇Facebook讚數／留言數／分享數各自顯示，不相加；主題卡若顯示互動數，明示為最新一次分享。
4. 原兩篇網址仍可用；較早篇導向主題頁對應段落。分享網址及上一／下一篇不再形成兩張重複內容。

## 業務規則與界線
54份原始Markdown保留為單一真相，展示清單為53項。只按明確兩slug分組，不按作者姓名合併所有人或其他主題。
兩篇的6張原照片按來源內順序保留，頁面按日期從早到晚閱讀，原文逐字不動。
留言資源僅收可讀且可核對的完整URL，優先作者補充；不把短網址截斷文字猜成網址，不把一般留言改充原文。來源若只能定位貼文，就標「來源貼文」，不假稱精確留言連結。
保留現有所有其他文章、Ambassador識別、篩選、低調hover、影片與更新偵測。

## Acceptance Criteria
- 首頁／兩個原作者頁只有一張主題卡，搜尋兩來源的關鍵詞均能找到它；日期以最近分享顯示。
- 主題頁含兩篇完整原文、6照片、各自來源／日期／統計；原統計不相加，來源明確。
- 較早篇舊URL在靜態部署可到主題頁實際存在的anchor，原primary URL維持可用。
- 留言資源的label、完整目的URL與來源經查核，點擊能直接開目標；沒有把未查證推薦混進。
- 照片lightbox、作者／日期篩選、前後文章導覽與其他52個展示項目正常；原有媒體不變。
