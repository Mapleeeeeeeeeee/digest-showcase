【聚會回顧】 Eric Lin （Apersona）：從 System Prompt 到 Persona Memory  
  
上一場 Claude 聚會，Apersona 的 Eric Lin 帶來一場非常誠實的 talk。他花了三個多月做一個「把人格壓進 AI」的 side project，跑過付費 POC，也在今年放棄了原本的路線。這場分享把哪些行不通、為什麼行不通、下一步怎麼走，全部攤開來講。  
  
◐ 01 / 關於 Eric  
  
Eric 過去十年都在做產品落地。他經營過代購平台（疫情期間收掉），後來創辦電商工具\- 藍莓並在去年出場。在藍莓時期，他們很早就把 GPT\-4 帶進銷售頁生成，把商家原本二十分鐘的工作，縮短到兩三分鐘，在舊金山累積了上百個用戶。去年他協助一家美國  AI 大模型公司，跑了十幾家台灣一級企業，包含金控與公部門，看到 AI 導入商務場景的共同痛點：無法正確抓出細節、系統太複雜、資料找不到。  
  
回頭看這十年，他的總結很妙：無論做什麼產品，軟體的本質好像一直都是排程，在最短的時間、最少的耗費之下，讓產品落地。  
  
◐ 02 / 起點：AI 怎麼做就是不像  
  
Apersona 的起點是一個大家都遇過的問題：無論是自己搭的 AI 助理，還是幫金控底下某個部門做的客服機器人，怎麼調就是「不像」。不像那個人、不像那個部門、不符合最細節的規則。  
  
三、四個月前，Eric 把這個問題變成 side project。團隊組成也很有趣：一位在美國做水文研究的 PhD，因為水庫興建的影響評估需要模擬大量周邊居民的人格與心理反應，累積了大量 persona 建模經驗；另外兩位是 Eric 前公司合作過的資深工程師，分別在台灣 AWS 與日本的金融機構。  
  
◐ 03 / 第一版 PFC：25 維參數引擎  
  
第一版的核心假設是：只要人格描述夠完整，LLM 就能穩定重現同一個人。他們把五百多篇文件、筆記、email 壓縮成 system prompt，並打造了一個由 25 維參數構成的數學引擎，依據人與人互動的心理學架構，從淺層互動到深層決策去定義一個人格。  
  
淺層與深層的差別，Eric 用一封真實的 email 說明。幾週前一位 VC 來信問：能不能用 Apersona 做人格 profile，幫他從每週看二十家新創提高到三十家？注意，不是兩百家，因為兩百家就變成 spamming。這種深度互動不像台上聊天，它需要抓住每位 founder 真正在意的事，因為好的新創同樣在評估這個 VC 有沒有讀懂自己。要在 AI 架構下還原這種深度，同時兼顧 token 效益，不能一送進去 context window 就爆掉，是整個引擎最難的部分。  
  
◐ 04 / 踩到的坑  
  
付費 POC 跑完，Eric 誠實列出結構性的問題：  
Context loss 始終無法擊敗。像一個漏水的水桶，只能不斷縫縫補補  
同一個 harness 裡的資料污染問題。客製化隔離做得到，但難以 production 化  
不可逆壓縮。細節、矛盾與來源關係在壓縮過程中消失，錯誤來源無法定位  
模型依賴。每個模型的漂移方式都不同，Claude 的漂移跟 GPT 的漂移不一樣，一次推出三個新模型，調優就要往三個方向拆散。前沿模型每次迭代，先前約三成的工作直接不知道怎麼辦  
幻覺依然大量存在。無法分層。事實、語氣、決策深度全部混在一起  
  
最有感的例子是 Eric 自己的測試。2020 年他因疫情收掉第一家公司 旅遊代購平台，AI 回溯這個決策時，判定他是務實的決策者，收得漂亮，事後看這確實是對的決定，畢竟疫情一路燒到 2022 年。但當下的他一點都不想收，平台上還有十萬用戶資料、五千多個賣家，也正在談跨國倉儲 與 剛啟動的機場免稅店合作。AI 缺少足夠的 context 去還原當下的心境，只能給出合理化的判讀。  
  
更普遍的問題是：如果今天現場參加Claude meetup的 七十位 founder 把自己的故事壓縮後送進 AI，它可能會把其中四十位判定成很相似的人。電機、資工、資管背景， 10多年來創業過，也失敗過但沒有放棄，等等，但我們自己知道，我們每個人的故事都不大不相同。  
  
原因就是會到語言模型，將中間太多角色細節被丟掉了，它不知道什麼時候該抓大、什麼時候該抓小，也就無法準確代理你的行為與決策。  
  
◐ 05 / 轉折：要保存的不是 Prompt，是可查詢的人格記憶  
  
轉折點在這裡：System Prompt 不是人格本體，只是一張靜態快照。真正要保存的是 Memory \+ Rules \+ Evidence，而 Prompt 退回它真正適合的位置，變成 runtime 時才動態編譯的產物。用 Eric 的話說，是從「描述一個人」走向「維護一個人的可運算記憶狀態」。  
  
◐ 06 / 現在：PFC vNext 與 Activation Level  
  
新版架構把 PFC 變成 LLM 前後的控制層：INGEST → PROCESS → ROUTE → COMPILE → GENERATE → VERIFY。資料先做事件化與符號化，加上深度標籤，標記每件事在當下是 level 1 到 level 4 的哪種嚴重程度。記憶庫則依據人類社會心理運作：金錢壓力、感情壓力、工作壓力、家庭壓力發生時，這個人格應該怎麼表現。遇到沒看過的情境，模型必須認出這是一片迷霧，誠實承認我看不到，而不是硬推。  
  
搭配的是 Activation Level 的概念：人格不是 ON／OFF，而是 L0 到 L4。回一封 bug 回報的 email，走直接的 task 流程就好，完全不需要人格；寫作回信載入語氣；決策建議載入規則與偏好；只有代理與策略層級才需要 deep persona。人格越深不等於越好，正確的產品行為是只在必要時升級，同時省下 token、延遲與錯誤傳播。  
  
◐ 07 / 下一步：Persona OS  
  
現在的客服機器人，不管是房仲、保險還是其他產業，都是 single task 的 memory 應用，而且經常搭配 清理記憶，來維持 agent 維持穩定性。  
  
Apersona 想回答的問題是：能不能做出長期對話、而且可轉移的人格層？方向包括 Portable Persona Memory（人格與模型解耦，多模型讀同一個 persona）、Persona Graph（事件、人物、決策、規則、矛盾形成可追溯圖譜）、Multi\-Agent Identity（不同 agent 共享同一個人，載入不同人格切片）、以及 Counterfactual Simulation（從模仿語氣，進一步測試這個人可能怎麼選）。  
  
判斷標準也變了：不是像不像，而是能否持續、可驗證地保持同一個人的決策結構。  
  
◐ 08 / 五個結論  
  
System Prompt 還存在，但它是 runtime 產物，不再是人格資料庫  
RAG 不等於 Persona。RAG 找資料，PFC 決定哪些資料代表這個人  
Symbolic layer 是關鍵。把事件、規則、狀態與未知顯式化，才能驗證  
人格必須可分層啟動，不是每個問題都值得載入完整人格  
真正的護城河是長期狀態。可追溯、可更新、跨模型的人格記憶才有複利  
  
Same person\. Different tasks\. The right context\. Every time\.  
  
謝謝 Eric 把一個還在路上的產品，連同失敗與修正一起帶到現場。這正是我們希望聚會有的樣子。
