Claude Skills Are Not Plug\-And\-Play｜Andy Wu，七位數電商 Shopify 賣家執行長  

–  

幾週前在台北 Claude 社群聚會上，Wuberlife Brands 的 Andy Wu 在 Futureward Central 為商業與營運人士進行了一場 demo 與分享。  

Wuberlife Brands 是一家專營高品質戶外結構與生活產品的線上零售商。Andy 是一名電商營運者，沒有技術背景，過去 2 個月來持續使用 Claude Code 來驅動他的業務。  

他一開始並非使用 Claude Code，而是先嘗試了 make\. com。make\. com 在自動化方面很有用，但他發現它相當脆弱。每個供應商的資料格式都不同，即使是小小的邊緣案例也會層層疊加成複雜的維護噩夢。他展示了一個有五家供應商的真實訂單流程，複雜程度一目瞭然。  

他後來嘗試了 Manus，這讓他真正感到興奮，因為他第一次能夠看到 AI 推理完成任務的過程，但一個他本來 30 秒就能完成的任務，Manus 卻花了 3 小時。後來 Claude Code 推出了 Claude Skills，他就一直用到現在。  

–  

在 Andy 看來，網路上那些聲稱設定一個 skill 只需 30 分鐘的說法都是誤導。對他來說，skill 需要 5–6 小時來微調，複雜的 skill（例如網頁爬蟲）甚至可能超過 20 小時。Claude 完全不了解你的業務，所以在沒有大量 context 的情況下，告訴它「幫我的業務寫 SEO 內容」根本沒有用。  

建立一個 skill 所需的工作量，跟撰寫一份好的 SOP 是一樣的——每一個點擊、每一種格式、每一個邊緣案例都必須清楚說明。他的 skill 檔案平均約有 500 行 markdown，並附有 3–5 個輸出範例。大多數公司都有那份 700 頁的 SOP 文件，建立一個好的 skill 所需的細節程度應該差不多。你可以直接把它餵給 Claude，讓它幫你把 skill 建立起來。  

Skills 只是一個起點，不應該被視為成品。他從 GitHub 下載，掃描是否有 prompt injection，讀 readme，試用看看，一分鐘內就能判斷它對他的業務是否有用。找到合適的之後，他才開始針對自己的業務、工作流程和輸出標準進行調整。  

–  

→ 使用案例一：SEO 內容流程  

Andy 做 SEO 超過十年，對自己的利基市場瞭若指掌，不想管理一整個包含寫手、規劃師、上傳人員、圖片優化和 SEO 專員的內容團隊，所以他建立了一條 SEO 流水線：  

關鍵字研究 → 資訊差文章規劃 → SEO 內容撰寫 → 人工審核  

以前需要 4–5 個月才能建置完成的流程，現在只需約 2 週。這些 skills 是模組化的，彼此之間會互相呼叫。主要的 SEO 內容 skill 會呼叫一個獨立的「資訊增益」skill（用來搜尋競爭對手不會有的科學論文和統計數據）以及一個關鍵字資料庫 skill。他將每個 skill 設計成以下一個 skill 所需的格式輸出資料，就像把整理好的資訊交接給下一個部門一樣。  

→ 使用案例二：Shopify 產品上傳  

他的供應商以不同格式發送雜亂的試算表。每一個產品，他都需要重新命名圖片、撰寫 alt text、撰寫產品文案、填寫 metafields 和 meta objects、以 SEO 檔名壓縮圖片。每個產品要點擊超過 35 次。  

他的 Claude Code skill 現在全部包辦，100 個產品完整優化上傳只需約 10 分鐘。他使用從 skill 內部呼叫的 Python 腳本，這些腳本他沒有自己寫，也不完全理解，因為他不是程式設計師。但他告訴 Claude Code 去研究 Shopify API 然後完成這件事，它就做到了。  

→ 使用案例三：透過 Klaviyo API 進行電子郵件行銷  

和許多行銷平台一樣，Klaviyo 的介面是拖放式的。Andy 讓 Claude Code 閱讀 Klaviyo API 文件，並建立了一套流程：  

活動簡報 → 生成文案 → 透過 API 建立活動 → 人工審核  

他不建議對任何有實際業務影響的事情使用一次性提示。他試過一次，覺得第一個輸出結果很差。他也發現 Klaviyo 官方的 MCP 限制太多，因為它只允許建立活動，不能撰寫或排程流程，這就是他整體上傾向使用直接 API 而非 MCP 的原因。  

–  

在日常操作系統方面，他同時並行運行 4–5 個 Claude Code 實例，這需要每月 100 美元的方案。每天早上醒來，他先設定 5 個任務，完成早晨例行事項，回來時就已經完成了 70%。這已經大幅改善了他的日常工作節奏。  

他的幾個關鍵心得：  

→ 在 Anthropic 推出 memory\. md 之前，他就自己建立了一個名為 session\-notes\. md 的記憶檔案，用來記錄已完成的事項、接下來要做什麼，以及需要哪些 skills。他在每次 session 開始時載入這個檔案，它的功能就像 Claude 實例之間的部門交接文件。  

→ 如果讓 Claude Code 自行運作，它只能正確完成約 75% 的品質檢查。他的解決方法是讓它每次都將檢查清單逐條列印到螢幕上，並要求人工簽核。這就是他確保輸出品質穩定的方式。  

→ 同時運行多個實例時，他為每個實例分配一個「支柱」，也就是一個領域或專案。每個支柱的核心事實來源存放在一份文件中。這是他吃了苦頭之後學到的——曾經有一個 Claude 實例覆蓋了另一個實例的工作成果。  

→ 遇到技術問題時，他將問題截圖丟進 Claude Code，請它修復，95% 的情況下都能解決。你也可以直接在這裡丟入檔案和 PDF 進行故障排查。  

→ 出門和朋友吃晚餐時，他使用遠端控制讓 Claude 持續運作，而不是閒置。  

–  

Claude Code 特別適合營運工作，因為營運工作本質上是重複性的。一旦 skill 建立完成，附上一段使用教學錄影交給初階員工就好。這就是現在的員工培訓面貌。你不需要開發人員，不需要提 Jira 工單等三週。你只需要描述你想要的結果。  

他不認為 Claude Code 會取代營運人員。它實際上會讓他們更有力量，因為 Claude 無法判斷好的商業策略。它不知道在你的特定業務中，哪些流程是高價值的，哪些是低價值的。懂得這些的人，現在可以用 10 倍的速度將這份判斷付諸行動。  

在招募方面，你現在可以純粹以軟實力為標準——好奇心、溝通能力和學習意願。所有技術執行面現在都由 AI 處理。比起擁有特定技術資歷的人，他更看重能夠快速上手工具並靈活應變的人。  

他接下來想嘗試的事：  

→ 競爭對手價格爬蟲 → Google Ads 自訂報表 → 供應商採購單建立 → 月底對帳  

他也在測試 Claude 的電腦使用功能，目前處於研究模式，因為用於面向客戶的工作風險還是太高。  

「Claude Code 是史上最超值的百元月薪員工。」
