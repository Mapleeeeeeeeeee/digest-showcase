昨天， Tammy 分享了她的團隊如何把所有 SaaS 工具換成自己用 AI 打造的版本，現在以超過 30 個 agent 支撐他們的事業 Numbers Protocol。  
  
以下是這場分享的重點整理。  
  
留言處有她的簡報連結，包含密碼。也有一個連結可以留下 email，跟他們團隊保持聯繫。

⬢ Tammy 分享回顧：打造一個 AI Native 的工作環境  
  
在這場 Claude Code × Founders 聚會上，Numbers Protocol、DT42\.ai 與 Omni AI 創辦人 Tammy Yang 分享了她的團隊在過去一年半，如何把公司大部分的軟體自己重寫一遍，讓整間公司真正圍繞 AI 運作。  
  
Tammy 是 Manchester University 粒子物理學博士，曾任 Canonical（Ubuntu）HP 專案技術工程主管，有超過十五年的軟體開發與資料科學經歷。正因為不是商業運營出身，她對「公司該怎麼運作」沒有既定想法，可以不斷追問：為什麼要用這個軟體？為什麼這件事不能交給 AI？這種心態讓公司得以真正釋放 AI 的能力。  
  
當然，也有一些先天條件：他們是十人以下的小公司、全員遠端、原本就有雙語、跨時區、跨國溝通的強烈需求，而且全員對新技術接受度高。  
  
關於 AI Native，她先引用了 Gemini 的定義：整個組織的系統、資料庫、角色與工作流都圍繞 AI 設計，由 AI 參與分類、查詢、生成與審核。然後給出她自己的版本：AI 自己決定要做什麼、自己做好、不要煩我。只有真正無法達成的，例如親自參與今天的活動，才由人處理。  
  
⬢ 起點：只是想幹掉 Slack 的月費  
  
這一切始於 2025 年 3 月，動機非常實際。多一個人，就多一筆費用，Slack 覺得合理，她覺得不合理。而且多數 SaaS 只有 10% 的功能是你需要的，卻常常因為另外 90% 的功能把你需要的部分弄壞。那時他們完全沒有要做「公司作業系統」的打算，就只是覺得為了聊天付這筆月費很不划算。  
  
大家覺得幹掉 Slack 很困難，原因可以收斂成三點：它是全公司對內對外的溝通核心、上面累積了大量資料、綁定了非常多自動化。但只要拆開來看，真正難的只有溝通這一關，因為它需要全公司取得共識。所以第一步不是做什麼 AI，而是先建一個自己的 chat，讓所有人能在裡面順暢工作、串接資料與 webhook，並且把 agent 帶進來。溝通解決之後，資料與自動化都只是技術問題。  
  
⬢ 一不留神，就走了很遠  
  
頭過身就過。接下來 Asana、Airtable、Zapier 等七八年來疊加的各種 SaaS 一個一個被取代：group chat、專案管理、task management、issue tracking、workflow automation、internal tools、資料，到 AI agents，慢慢匯聚成同一個平台。他們把給人的系統命名為 Z。  
  
⬢ 真正拿回來的，其實不是軟體  
  
重建不是為了重建而重建，而是拿回「公司到底是怎麼工作的」那份數據。哪些功能每天真的有人用？哪個 workflow 大家一直卡住？哪個流程一直需要人工 workaround？哪個 task type 最常 overdue？Tammy 在會中舉了一個例子：一個專案開案時排了三個人，結案時卻變成八個人，這種長期低估人力的模式背後可能是流程問題。但當這些工作散落在十幾個 SaaS 裡，你永遠沒辦法 100% 用 data\-driven 的方式改善流程。  
  
⬢ 最後一個問題，以及第二個系統  
  
把人的系統拿回來之後，還剩下一層跑在別人的平台上：agent 怎麼記憶、怎麼決策、怎麼被排程，原本分散在 Lovable、Claude Code、ChatGPT、Cursor 這些工具裡。於是他們建了第二個系統 Omni，專門給 agent。  
  
一間公司，兩個系統。Z 給人，Omni 給 agent。兩邊資料共享、agent 共享，人觀察 agent，agent 也觀察人，會主動提出建議、主動修復自己。兩個系統底下是同一套架構：GitHub 是核心，原始碼、修改歷史、部署邏輯都看得見，AI 讀完所有 repo 和 CI/CD，自己長出一層管理層，底下部署在 AWS、GCP、Firebase、Cloudflare 等既有雲端服務上。  
  
⬢ 一些數字  
  
系統完整上線至今 151 天，零斷線。公司有 59 個常駐 AI agent 每天自己上工、369 個常駐自動化 loops 與 schedules，單日自主執行次數最高紀錄是 1,473 次。最近上線的 400 個 PR 中，96% 由 agent 自己完成。從開發、行銷、業務、營運到財務，通通都交給 agent。  
  
他們用人的方式框架 agent：每月第一天，agent 會根據過往工作與收集到的資料回報自己的月度目標，人可以修改；接著 agent 自己長出每週目標與一週七天的排程。它們也知道週一到週五處理重要工作，週末只做不會造成大麻煩、不需要人來決定的事。  
  
⬢ 那工程師呢？  
  
把一切交給 agent 之後，工程師的工作往這裡移動了：資源衝突、空間不足、穩定度，還有收拾 agent 弄壞的系統。agent 一定會弄壞東西，就像人也會弄壞東西一樣，除了各種測試與自動修復機制，很多解法其實是非技術性的，例如調整 deployment 的時間。  
  
⬢ 我的一天  
  
轉型前後，Tammy 的 daily routine 有一個明顯的翻轉：使用電腦的時間從 70% 降到 18%，因為大部分執行都由 agent 在背後完成，人只需要花幾分鐘 review 與確認；使用手機從 15% 增加到 27%；線下生活從 15% 增加到 55%。不管是實體碰面，還是真正的人與人對話，都大幅增加。工作回到本質：溝通你缺什麼、想要什麼、需求是什麼，機器該做的事真的都交給機器了。  
  
⬢ 接下來呢？  
  
2025 年他們在問：這件事 AI 能改寫嗎、能取代嗎。2026 年，這些 agent 系統開始成形，成為公司能自己掌控的系統。2027 年的目標是讓 agent 不下線、不請假、不離職，這會涉及核心模型層的架設，甚至需要自己的模型，並讓 agent 真正理解公司文化，成為原生的員工。  
  
如果你或你的公司也正在 AI Native 的路上遇到卡點，Tammy 說他們大概都踩過了，歡迎寫信到 tammy@numbersprotocol\.io 跟她聊聊。
